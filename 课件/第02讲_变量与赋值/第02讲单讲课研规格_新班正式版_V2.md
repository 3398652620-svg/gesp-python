# 二、本讲核心定位

## 一句话定位

> **让学生理解：变量是程序给数据起的名字；`=` 是"把右边的值放进去"，不是"左右相等"；名字里装的东西可以换，换完之后程序记住的是最新的那个。**

## 本讲的两个认知台阶

本讲有**两道坎**，必须分清主次：

| 坎 | 内容 | 难度 | 处理 |
|---|---|---|---|
| 第一道 | `=` 不是数学等号，是"放进去" | 中 | 正式讲透，建立"先看右边"的阅读方向 |
| **第二道** | **名字里的东西可以换（重新赋值）** | **高** | **本讲重点，必须正面回应"为什么不直接改"** |

> **课研判断**：第一道坎如果不打穿，新班第03讲的 `x = x + 1` 必崩；
> 第二道坎如果不打穿，孩子会带着"变量没什么用"的疑问一路走到列表基础节点（原规划33，实际新班课号待确认），并以"为什么后面要 append，我提前写好不行吗"的形式**二次爆发**。

# 三、本讲为什么现在教

## 1. 从第01讲的真实局限出发

第01讲的信息卡是"写死的"：

```python
print("姓名：小明")
print("爱好：机器人")
print(10)
```

孩子立刻能感到别扭：

> 如果换成"小红"，我要改三个地方；
> 如果这张卡还要用一次，我又要抄一遍。

**保存数据的需求，是孩子自己产生的，不是老师给的。**

## 2. 但必须诚实地承认：现在"提前写好"确实也行

**这是本规格最重要的一条设计决定。**

在第02讲这个时间点上，程序里所有数据都是孩子自己在键盘上敲进去的。因此当孩子问：

> "老师，那我直接改不就行了？为什么要写在下面？"

**他说的是一件当下完全成立的事实。** 此时孩子还没学过 `input()`，程序中没有任何"来自外部"的数据。任何"必须用变量才能变"的论证，在当前知识范围内都无法成立。

因此本讲的策略**不是辩论，而是演示**：

| 不做什么 | 做什么 |
|---|---|
| ❌ 论证"为什么必须能变" | ✅ 演示"写两行，屏幕上的结果确实不一样" |
| ❌ 引入未来的 input 来证明 | ✅ 用"游戏升级"这类孩子已有的真实经验说明 |
| ❌ 假装问题已经彻底解决 | ✅ 明确告诉学生"这个问题问得很好，以后会变得更重要" |

> **教学原则**：让事实说话，不让老师说话。
> 孩子的眼睛会告诉他"同一个名字，前后打印出来不一样"——这不需要说服。

# 五、本讲必须建立的核心认知

## 核心认知1：变量是数据的名字

```python
name = "小明"
print(name)
```

学生需建立：

> 程序把 `"小明"` 这个数据交给 `name` 这个名字保存；之后 `print(name)` 用的是这个名字当前装着的值。

**关键不是盒子的形状，而是：**

> **同一个数据只需要在一个地方写下，其它地方用名字去取。**

## 核心认知2：`=` 是"放进去"，不是"相等"

```python
age = 10
```

本讲必须建立稳定的阅读方向：

> **先看右边是什么值，再把它交给左边的名字。**

教师可用一句固定句式强化：

> "把 10 **放进去**，放到的名字叫 `age`。"

**明确不讲**：数学意义的"等于"。要让孩子知道这里的 `=` 是**一个动作**，不是一个判断。

## 核心认知3：名字里装的东西可以换（本讲重点）

```python
age = 10
print(age)      # 10

age = 11
print(age)      # 11
```

学生需建立：

> **同一个名字，前面看是 10，后面看是 11——因为中间那句话把它换掉了。**

**本讲的固定追问句式（贯穿全课）：**

> **"这个名字现在装着什么？"**

## 核心认知4：变量可以装不同形式的数据

```python
name = "小明"      # 文字，要引号
age = 10           # 数字，不要引号
height = 1.52      # 带小数点的数字，不要引号
```

延续第01讲的"数字 vs 文字"，不引入 `int/float/str` 术语。

## 核心认知5：变量名要合法、要看得懂

**正式讲（会撞上、会立刻用到）：**

- 名字要有意义：`name` 比 `a` 好；
- 不能用数字开头：`2age` 会报错；
- 大小写敏感：`Age` 和 `age` 是**两个不同的名字**。

**轻量带过（提一句，不深究、不列清单）：**

- 只能用字母、数字、下划线；
- 不能有空格；
- 不能用 `print` 这类 Python 自己留着的词。

> **收窄理由**：四年级学生记不住 5 条抽象规则，但"要有意义"和"不能数字开头"是**写代码时当场就会撞上的**。讲在撞上的那一刻最有效。

## 核心认知6：`name` 和 `"name"` 不是一回事

```python
name = "小明"
print(name)      # 小明    ← 取名字里装的值
print("name")    # name    ← 直接输出这四个字母
```

这是本讲最重要的辨析冲突，也是学生最常见的错误来源。

## 核心认知7：好的变量名让程序更易读

```python
a = "小明"      # 合法，但看不懂
name = "小明"   # 一眼就懂
```

目标不是命名规范，而是建立：

> **变量名最好能表达它装的是什么。**

## 核心认知8：变量要先定义，才能用 ★

```python
name = "小明"     # ← 这一整行，叫"定义变量"
print(name)       # ← 定义之后，才能用它

print(score)      # ❌ 从没写过 score = ...，程序会说"我不认识这个名字"
```

**这是必须显式强调的一条**，不能默认孩子会自己悟出来。

- **第04幕**点明：这一整行叫 **"定义变量"** —— 先定义，后面才能用它
- **第10幕**回收：程序说"不认识这个名字"只有两种可能 —— ① 拼错了（大小写）② **还没定义过**

> **为什么要专门强调**：学生刚学会 `print` 时，很容易"想到什么就打印什么"。这一讲是他们第一次遇到"名字必须先存在"的约束。此处讲清楚，能省掉后面大量"我不认识这个名字"的报错。

# 九、本讲必须避免的错误教学

## 1. 把变量永远讲成"盒子"

盒子比喻可以入门，但必须过渡到：

> **名字当前装着什么。**

## 2. 把 `=` 讲成数学等号

必须明确它是**一个动作**。

## 3. 试图"论证"为什么必须能变

**本讲最大的教学陷阱。**

在孩子还没学过 `input()` 的时候，任何"必须能变"的论证都站不住脚。正确做法是**演示事实 + 承认问题的合理性 + 留下钩子**，而不是把老师的世界观强加给孩子。

## 4. 命名规则变成背诵课

目标是会判断、会避错、会起有意义的名字。

## 5. 提前引入 `x = x + 1`

只作为**课尾悬念**出现，不解释、不练习。

## 冲突3：重新赋值 / "为什么不直接改"（本讲核心）

```python
age = 10
print(age)

age = 11
print(age)
```

### 学生的真实提问

> "老师，那我直接把上面的 `10` 改成 `11` 不就行了？为什么要在下面再写一行？"

### 这个问题的真实结构

这不是一个刁难，而是**三个不同层次的问题**混在一起：

| 层次 | 真实疑问 | 本讲能否回答 |
|---|---|---|
| 第1层 | 为什么要有名字？ | ✅ 能，且必须回答 |
| 第2层 | 数据为什么会变？ | ⚠️ 只能演示，不能论证 |
| 第3层 | 谁是数据的来源？ | ❌ 不能，要等后续input节点（原规划08，实际新班课号待确认） |

### 本讲应对话术（三步）

**第一步：承认他当下是对的，不辩论。**

> "你这个问题问得**特别好**。而且老师要先告诉你——**你说得对**。
>
> 我们现在程序里的数字，都是你自己一个字一个字敲进去的。既然都是你敲的，那你直接改上面那行，当然也行。"
>
> **（先把孩子的合理性确认下来，他才会继续听你说。）**

**第二步：让事实说话，演示两段的差别。**

> "那我们做个实验。先看这段——"
>
> ```python
> age = 10
> print(age)
> ```
>
> "如果我把上面那行直接改成 11，屏幕上是 11。
> 现在换一种写法——"
>
> ```python
> age = 10
> print(age)
> age = 11
> print(age)
> ```
>
> "跑一下，屏幕上出来的是什么？是 `10` 和 `11` 两行。
>
> 注意看：**同一个名字 `age`，第一行 print 出来是 10，第二行 print 出来是 11。**
>
> 中间发生了什么事？——**那行 `age = 11` 把它换掉了。**"

**第三步：用"信息卡新增学校栏"给一个当下成立的理由。**

> **【为什么不用"游戏升级"】** 游戏等级这个例子不好用：孩子会反驳"我知道我会升级啊"，而且升级是他能预想到的事。**改用信息卡自己长出来的新一栏**，孩子一看就懂"现在还真的填不了"。

> "老师用我们自己的信息卡来打个比方。假设你的信息卡，今天要**多加一栏：学校**："
>
> ```text
> ==========
> 我的信息卡
> 姓名：小明
> 爱好：机器人
> 年龄：10
> 学校：______      ← 现在能填吗？
> ==========
> ```
>
> "老师现在就给你填上——**清华大学**，行不行？"
>
> （孩子会笑，会说"不行"）
>
> "为什么不行？——因为**这件事还没发生，你是真的不知道**。
>
> 那怎么办？只能**等知道了，再填**。在程序里，'再填'就是 —— **再写一行赋值**。
>
> 所以，为什么有时候我们不在第一行把值写死，而是**到后面再写一行**？因为那个值，**写代码的时候还不知道**。"

**第四步：明确告诉学生"这个问题到后面会变大"，并留下钩子。**

> "最后老师要跟你讲一句真心话：
>
> 你今天问的这个问题，现在看起来好像不重要——因为数字都是你自己敲的。
>
> 但是请**记住这个问题**。因为以后，程序里的数字会**从外面来**——你输入什么，它就是什么。到那时候，你就**没办法提前写好了**。
>
> 到那一天，老师会回来找你，告诉你答案。"

### 为什么必须用这个四步（课研理由）

1. **承认合理性** → 保护孩子的提问勇气。否定一个真问题，孩子以后就不问了。
2. **演示而非论证** → 只依赖已学知识，不偷跑未来内容。
3. **生活经验做支点** → "游戏升级"是孩子真实经历过的、不可提前写好的一次变化。
4. **留下钩子** → 这句话会在后续input节点（原规划08，实际新班课号待确认）回收，届时可以对学生说："还记得你在第2课问的那个问题吗？今天答案来了。" 孩子会有一瞬间的"原来是这样"——这是**由他自己提出的问题被解答**，教学效果远好于老师主动讲。

# 十一、本讲程序思维训练点

## 4. 阅读方向：先右后左

建立 `=` 的稳定阅读习惯，为新班第03讲 `x = x + 1` 做直接铺垫。

# 十二、本讲题型递进

## 第一层｜基础识别
- 指出变量名和数据分别是什么；
- `name = "小明"` 后，`print(name)` 输出什么。

## 第二层｜同构
- 换成 `city` / `score` 等其它名字，预测输出。

## 第三层｜辨析
- `print(name)` vs `print("name")`；
- 哪个是变量，哪个是字符串。

## 第四层｜命名合法性判断
- 从 5～6 个名字中挑出能用的、不能用的，并说明原因。

## 第五层｜**当前值（本讲重点）**
- 连续两次赋值，问最后输出什么；
- 中间加一次 print，问两行分别输出什么。

## 第六层｜找错
- 变量名加了引号；
- 变量名数字开头；
- 大小写写错导致"名字不存在"。

## 第七层｜小综合（独立任务）
- 用 3 个变量保存姓名、年龄、爱好并输出；
- 进阶：把第01讲的信息卡用变量重写。

# 十六、本讲常见错误及处理原则

| 错误 | 代码 | 处理 |
|---|---|---|
| 变量名加引号 | `print("name")` | 明确变量名与字符串边界，现场对比运行 |
| 数字开头 | `2age = 10` | 回到命名规则，不展开词法分析 |
| 名字有空隙 | `student name = "Tom"` | 说明名字必须连在一起 |
| 用关键字 | `for = 10` | 说明 Python 把某些词留给语法使用，不列清单 |
| 大小写不一致 | `age = 10` 后 `print(Age)` | 强调大小写敏感，指出"这是另一个名字" |
| 把 `=` 当"等于" | — | 固定句式："把右边的值**放进去**" |
| **认为旧值还在** | `city="深圳"` → `city="广州"` | 运行验证 + "被新的盖住了" |

> 处理原则：**现场运行 > 口头解释**。四年级学生对"屏幕上发生了什么"的信任度远高于老师的话。

# 十七、本讲能力出口

课末学生必须至少能做到：

1. 独立写出 `name = "小明"` 形式的赋值语句；
2. 用 `print(变量名)` 输出变量里装的值；
3. 说清 `=` 在这里是"把值放进去"；
4. **说清同一个变量可以换值，换完之后程序记住的是新的那个**；
5. 能判断一段两三次赋值的代码最后输出什么；
6. 能区分 `print(name)` 和 `print("name")`；
7. 能判断常见变量名能不能用（至少能识别"数字开头"和"大小写不同"两种情况）；
8. 能独立写一个 3～6 行的变量程序。

- `+=`；
- 变量交换；
- input / 类型转换 / f-string；
- 完整关键字表；
- Trace Table 逐行跟踪；
- 作用域、内存模型。

# 十九、本讲自然显性成果

> **无，不强行包装。**

本讲仍然必须安排学生独立完成一个 3～6 行的变量程序。

**本讲推荐的实战任务：把第01讲的信息卡用变量重写。**

第01讲的卡片（写死版）：

```python
print("==========")
print("我的信息卡")
print("姓名：小明")
print("爱好：机器人")
print(10)
print("==========")
```

本讲的卡片（变量版）—— 改称「资料卡」：

```python
name = "小明"
age = 10

print("==========")
print("我的资料卡")
print(name)
print(age)
print("==========")
print("欢迎")
print(name)
```

> **这个任务的独特价值**：孩子手里**有一份"改之前"和"改之后"的对比**。
> 一眼就能看到：数据被提到了最上面、集中在一起，以后要改"小明"，只改一行就够了。
> 这是本讲"为什么要有名字"最直观的证据，而且是孩子**自己动手做出来的**。
>
> 而且 `name` 在卡里**出现两次** —— 改 1 行，输出里 2 处同时变，"**改一处全生效**"看得见。

> ### ★ 重要修订：为什么不用上节课那张信息卡做练习
>
> 第01讲的信息卡，输出是 `姓名：小明` —— **文字和数据混在同一行**。
> 要用变量做出**一模一样**的输出，只有两条路：
> - 逗号：`print("姓名：", name)`
> - 加号拼接：`print("姓名：" + name)`
>
> **两条都超出本讲范围**（第01讲已明确"多内容逗号输出"不作为核心要求；加号拼接更是没学过）。
> 因此本讲练习**另做一张"资料卡"**：每个数据单独打印一行，全程只用 `print(变量)`，**不引入任何新语法**。
>
> 上节课那张卡**不做改造**，留到以后学过字符串拼接再回来。
>
> **禁止**：本讲课件与练习中**不得出现** `print("文字", 变量)` 这类逗号多参数输出。

**命名规则**：叫「资料卡（变量版）」即可，不要包装成"项目""大作"。

可表达为：

> 本节是孩子正式班的第二课，也是整套课程第一次进入"程序状态"的一课。孩子学习了 Python 中最核心的概念——**变量**：程序可以给数据起一个名字，之后通过这个名字反复使用它。
>
> 课堂中孩子重点理解了两件事：

> 孩子还第一次独立把自己的"信息卡"程序从"数据写死"改写成了"用变量保存"，亲手体会到"数据集中在一个地方、改一处就全部生效"的好处。这是后续学习循环、累加、算法的重要基础。

不要只写：

> 今天学习了变量和赋值。

后者看不见真正能力目标。

# 二十一、本讲给第03讲留下的接口

第02讲结束后，学生已经：

- 会用 `名字 = 值` 保存数据；
- 会用 `print(名字)` 取值；
- 知道同一个名字可以换成不同的值；
- 知道程序读到的是"到那个位置为止最后一次放进去的值"。

但目前只处理：

```python
age = 10
```

**右边是一个"直接写好的值"。**

下一讲自然提出：

```python
age = 10
age = age + 1
```

问题：

> **`age` 出现在 `=` 两边，程序到底怎么执行？**
> **右边的 `age` 是谁？它加完 1 之后，谁变了？**

- 从第01讲信息卡的真实痛点自然引出变量；

# 二十三、本讲最终课研结论

第02讲是整套课程第一次真正进入「程序状态」的课。

它不是简单教：

```python
x = 10
```

而是让学生开始理解：

> **程序可以给数据起名字；这个名字里装的东西可以更换；程序在某个位置读到的，是到那里为止最后一次放进去的值。**

而本讲最需要小心的地方，是那个几乎每个孩子都会问的问题：

> **"老师，那我直接改不就行了？"**

面对这个问题，本讲的态度是：

> **先承认他当下是对的，再让他用眼睛看到"换了之后会怎样"，最后把这个问题郑重地留到以后。**

本讲只把这扇门打开。

第03讲再正式进入：

> **状态怎样一步一步变化。**
