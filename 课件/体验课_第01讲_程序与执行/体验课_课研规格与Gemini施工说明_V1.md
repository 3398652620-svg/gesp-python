# 一、课程身份

这节体验课就是正式第01讲《程序与执行》的体验版路径。

学生试听后如果报名，本节直接计入第01讲，下一次进入第02讲《输出与基本数据》。不要体验课上一套内容，报名后又重新上一次第01讲。

体验版与正式第01讲知识边界一致，但节奏优化为：

> 更早碰到真正的 Python，更快获得“我真的让程序跑起来了”的反馈，然后再回头建立程序认知。

# 二、体验课真正要展示什么

不是展示 Python 有多酷、能做多少游戏、AI 多强、老师代码多炫。

真正应该让孩子和家长看到：

> 孩子正在学习怎样读程序、预测程序、修改程序、验证程序，而不是跟着老师复制结果。

体验课结束时，孩子至少完整经历：

> 看代码 → 先猜 → 运行 → 观察 → 修改 → 再运行

# 三、四个硬目标

## 1. 前10分钟内运行真实 Python

不要先讲20分钟“什么是编程”。

前10分钟内，让学生看到并运行极简代码，例如：

    print("你好")
    print("我是小程序员")

此时不正式拆 print() 语法。教师只说：

> 今天先把整行当作一条“让电脑显示一句话”的指令。括号、引号为什么这样写，后面正式再拆。

必须优先让学生真的改过一次代码、真的运行出一次结果。

## 2. 至少两次“先预测，再运行”

不能退化为老师讲、点按钮、看动画。

至少两次明确要求学生先说、先选或先写结果，然后才运行验证。其中至少一次与代码执行顺序有关。

## 3. 至少一次学生自己修改真实代码

学生不能只在网页上点击“我完成了”。

至少亲手完成一次：

> 修改代码 → 运行 → 看到结果变化。

零基础学生可以只修改引号内文字。动作快的学生可增加一条同构输出指令。

## 4. 有一个真实、朴素、可展示的结果

推荐“我的第一段 Python 程序 / Python程序名片”：

    print("你好，我是________")
    print("我喜欢________")
    print("今天我第一次运行了Python程序")

不是大型项目。真正成果是孩子自己修改并运行了一段真实 Python 程序。

# 四、推荐认知路径

这是认知路径，不要求 Gemini 按固定页数机械执行。

## 00～05 min｜模糊指令制造冲突

快速制造“人会猜，计算机不会替你猜”的冲突。

例如教师说“往前走一点”，追问：

- 一点是多少？
- 往哪个方向？
- 什么时候停？

也可以让孩子短暂扮演机器人。约5分钟即可，不要拖成低幼游戏。

## 05～12 min｜立刻运行真正的 Python

进入课前已经预置好的 Python 环境。

给：

    print("你好")
    print("我是小程序员")

先预测输出，再运行。

随后学生自己把第二行改成名字、喜欢的角色或爱好，再运行。

目标：

> 12分钟以内完成“看 → 猜 → 改 → 跑”。

## 12～22 min｜回头解释：刚才为什么能运行？

再逐步提炼：

- 指令需要明确；
- 程序是一组可执行的指令；
- Python 是描述这些指令的一种编程语言；
- 代码不是只告诉电脑“我想要什么”，而是把执行规则写清楚。

可加入极短现实顺序问题，例如“穿袜子 → 穿鞋”，为代码执行顺序搭桥。

## 22～37 min｜第一次真正读程序

给：

    print("准备")
    print("开始")
    print("完成")

先不要运行，要求学生预测输出顺序。

再利用动画或执行光标逐行展示真实执行过程，输出区同步变化。

关键变式：

    print("完成")
    print("准备")
    print("开始")

先问：

> 电脑会不会觉得顺序不合理，自动替你改回来？

再运行。

必须建立：

> 计算机按照你写下的程序执行，而不是按照它认为“合理”的顺序执行。

## 37～52 min｜我的第一段 Python 程序

零基础支架：

    print("你好，我是________")
    print("我喜欢________")
    print("今天我第一次运行了Python程序")

学生：

1. 修改自己的内容；
2. 预测会显示什么；
3. 运行；
4. 观察；
5. 可选调换两行顺序再次运行。

自然分层：

- 基础学生：完整骨架，只修改引号内文字；
- 动作快学生：前两行给出，第三行让学生模仿增加。

不要为了照顾快学生提前引入变量、input、if、循环。

## 52～64 min｜Debug 雏形：能运行也不一定正确

优先使用“能运行，但逻辑不符合目标”的程序：

    print("穿鞋")
    print("穿袜子")
    print("出门")

问：

> 这段程序能运行吗？

能。

再问：

> 但它完成了我们的目标吗？

由此建立：

> 能运行 ≠ 程序一定正确。

让学生经历：

> 找问题 → 改顺序 → 再运行。

如果课堂节奏很好，可以额外出现一个极轻符号错误，例如少一个引号，但不正式教授错误类型。

## 64～74 min｜体验课高潮：三关能力挑战

不要堆大量选择题。

第一关：看懂

    print("A")
    print("B")
    print("C")

问输出顺序。

第二关：预测变化

    print("B")
    print("A")
    print("C")

必须先预测，再运行。

第三关：真正修改

    print("我喜欢苹果")
    print("我喜欢足球")

要求学生改成属于自己的两句话，然后在真实 Python 中运行。动作快的学生增加第三条。

第三关不能只是网页按钮自报完成。

## 74～80 min｜能力收束，不做招生演讲

让学生自己回答：

1. 计算机会不会猜你的意思？
2. 三行代码会按照什么顺序执行？
3. 程序结果和预期不一样，第一步应该怎么办？

理想答案应包含：

- 不会替人猜；
- 按代码顺序执行；
- 检查并修改代码，再运行验证。

教师可最后收束：

> 今天真正学会的，不是背一条 Python 语法，而是开始像程序员一样想：我写下的代码，电脑接下来到底会怎么执行。

自然留下第02讲接口：

> 今天把 print(...) 当成了一整条显示指令，下一讲再正式拆开它，看看 Python 怎样表达文字和数字。

# 五、IDE / 软件操作硬约束

> 不得把体验课做成 IDLE / IDE 操作教程。

不要在课堂主时间详细讲：

- 怎么打开 IDLE；
- File → New File；
- Save As；
- 文件保存路径；
- 文件夹管理；
- Shell 与 Editor 的完整区别；
- 菜单栏；
- 编辑器快捷键大全；
- 怎样重新找到刚才保存的文件。

这些不是本节真正要展示的编程能力。

## 课前环境原则

所有能提前准备的内容，由教师课前准备好：

- 编辑器已经打开；
- 体验课文件已经打开；
- 第一段代码已经预置；
- 光标位置准备好；
- 运行方式统一；
- 尽量避免现场登录、配置环境、下载安装。

学生第一次操作只需要知道：

> 改代码。  
> 运行。

软件操作教学总量建议控制在2～3分钟以内，越无感越好。

正式课程后续再逐渐建立新建、保存、命名、打开和 IDE 使用习惯。

# 六、必须保留的程序思维

1. 指令明确性：计算机不会自动补全人的模糊意图。
2. 执行顺序：程序按照实际代码顺序执行。
3. 预测：运行前先想结果。
4. 验证：运行用于验证预测，不替代思考。
5. 修改：改代码会改变执行结果。
6. Debug 雏形：结果不符合目标时，回到代码找原因并修改。

# 七、知识边界

体验课仍然是第01讲。

可以体验性出现 print("...")，只作为已准备好的显示信息指令。

不正式教授：

- print() 语法拆解；
- 字符串完整规则；
- 数据类型体系；
- 变量；
- 赋值；
- input；
- 条件；
- 循环；
- 函数；
- 列表；
- Turtle。

不得为了视觉效果偷跑 Turtle、随机数、input、if、循环、列表、自定义函数、AI API、游戏框架。

体验课必须真实代表后续课程，而不是一次漂亮但虚假的烟花。

# 十、家长侧真正应该看到的价值

无需专门插入招生宣传页。

课程过程本身应该让家长看到：

- 孩子不是只看老师写；
- 孩子会先猜结果；
- 孩子会亲手修改；
- 孩子能解释代码顺序；
- 孩子出错后会尝试检查。

家长反馈可表达为：

> 本节孩子完成了第一次真实 Python 程序运行与修改，并重点建立“程序按照明确指令和确定顺序执行”的基础认知。课堂中孩子多次先预测代码结果，再通过运行验证，并尝试发现和修正程序与目标不一致的问题。这是后续变量跟踪、条件判断、循环和算法学习的底层程序执行能力。

# 十一、体验课教师诊断观察

体验课可兼作轻量诊断，但不是筛选学生。

重点观察：

1. 愿不愿意在运行前先预测；
2. 预测错后能否根据结果修正；
3. 能否理解代码顺序改变会造成结果改变；
4. 能否模仿已有结构修改一条代码；
5. 遇到错误时，是愿意找原因，还是只等待老师给答案。

区分“暂时不会”与“长期拒绝参与思考”，不要因为第一次不会就判断不适合编程。

# 十二、验收标准

## 必须有

- 前10分钟内真实 Python；
- 学生真实运行代码；
- 至少两次先预测再验证；
- 至少一次代码顺序变式；
- 至少一次学生亲自修改代码；
- 程序名片或同等自然小成果；
- “能运行但逻辑不对”的 Debug 雏形；
- 三关能力出口；
- 与第02讲自然衔接；
- IDE 操作教学极少。

## 不能有

- 前15～20分钟都没有碰 Python；
- 大量 Python 历史与用途宣传；
- 大量 IDLE 菜单操作教学；
- 把体验课做成保存文件教程；
- 提前正式教授 print 语法；
- 提前变量 / input / if / 循环；
- Turtle 炫技；
- AI 炫技；
- 只有动画没有学生预测；
- 只有网页点击没有真实 Python 操作；
- 大型项目包装；
- 真题、必考考点等标签式宣传；
- 学生页面出现课研内部语言。
