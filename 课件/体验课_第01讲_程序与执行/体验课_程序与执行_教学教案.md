# 体验课教学教案
## 课程主题：程序与执行 —— 计算机为什么能“听懂”代码？

> **课程体系**：GESP Python 一级 + Python 基础拓展 38 讲  
> **体验课定位**：正式第01讲的体验版教学路径（学生试听报名后直接计入第01讲，下一次课无缝进入第02讲《输出与基本数据》）  
> **适用对象**：小学三至六年级 Python 零基础 / Scratch 转 Python / 仅有浅显编程接触的少儿学员  
> **总课时**：90 分钟  
> **有效教学时间**：按约 80 分钟紧凑设计（预留 10 分钟课前破冰、环境就绪确认与课后沟通）  
> **上位依据**：课程总纲 V3.2、七阶段知识依赖 V1.1、38讲课程课次地图 V1.1、第01讲单讲课研规格 V1、体验课课研规格与施工说明 V1  
> **核心教具**：体验课单文件 HTML 互动课件、课前预置好的 Python 简易运行环境（IDLE / Thonny / 轻量 Python 终端）

## 一、 教学目标与四个硬指标

### 1. 核心素养与认知目标
1. **指令明确性**：理解计算机不是人类，不会“读心术”，普通程序不会自动知道程序员没写清楚的规则，写程序时不能指望计算机替我们补上没写清楚的步骤，只执行毫无歧义的**明确指令**。
2. **程序与语言本质**：理解什么是**指令**（最小动作单元）与**程序**（按确定规则与顺序排列的一组指令）；认识 Python 是一种编程语言，我们可以用它把要执行的规则写成代码（是人机沟通的桥梁）。
3. **自上而下顺序执行**：理解像今天学习的这种顺序程序，会按照代码“从上到下、一条一条依次执行”；计算机严格按照**写下的代码顺序**执行，而不是按照它觉得“合理”的顺序执行。
4. **Debug 雏形与程序员思维**：建立“能运行 $\neq$ 程序一定正确”的科学观念；当运行结果与预期不符时，第一反应是像小侦探一样**回到代码检查顺序与内容**，经历“找问题 $\rightarrow$ 改代码 $\rightarrow$ 再运行验证”。

### 2. 体验课四大硬指标达标清单
- [x] **硬指标 1（前10分钟碰真机）**：在 05～12 分钟内让学生第一次看到并亲手运行真实 Python 代码（`print("你好")` 与 `print("我是小程序员")`），并在 12 分钟内完成“看 $\rightarrow$ 猜 $\rightarrow$ 改 $\rightarrow$ 跑”。
- [x] **硬指标 2（至少两次先预测再运行）**：全课设计 4 次强制“先预测再验证”机制，其中第09幕与第11幕针对代码执行顺序进行严格预测对比。
- [x] **硬指标 3（学生亲自修改真实代码）**：学生至少亲手完成一次真实代码文本修改（改名字/爱好）并在真实终端中观察到结果即时变化。
- [x] **硬指标 4（真实、朴素、可展示的成果）**：完成人生第一张 Python 程序名片（`my_card.py`），三行独立修改的完整 Python 程序，动作快的学员支持仿写增加第 4 行。

### 3. 知识禁区硬约束（教师严格不可抢跑）
- ❌ **严禁正式讲授 `print()` 语法拆解**：今天整行仅作为一条“让电脑显示一句话”的指令，不讲函数、参数、括号嵌套，引号与数据类型的正式展开严格留给第 02 讲。
- ❌ **严禁提前引入后续语法**：严禁变量赋值、`input()`、`int()`、`if/else` 条件、循环、列表、自定义函数、Turtle。
- ❌ **严禁软件操作喧宾夺主**：课前环境必须由教师预置完毕，严禁把体验课讲成 IDLE 菜单、新建保存、文件夹路径管理教程（操作教学控制在 2 分钟以内）。
- ❌ **严禁功利化标签宣传**：课件与教案中严禁出现“真题”、“必考”、“考级冲刺”等标签化字眼，纯粹还原探索编程思维的本质乐趣。

## 三、 教师关键提问、互动引导与救场话术

### 1. 环节一：模糊指令冲突（幕 03）
- **教师提问**：“同学们，如果老师只对大家说‘请往前走一点’，大家敢走吗？为什么每个人走的步数都不一样？”
- **学生预期反应**：“不知道走几步！”、“不知道朝哪个方向走！”、“不知道什么时候该停下来！”
- **教师追问**：“完全正确！‘一点’、‘适量’是人脑在猜。但计算机没有人类的眼睛和大脑，如果我们给机器人小派下达‘往前走一点’，大家看屏幕（老师点击演示1或按空格键）——小派在原地晃晃悠悠直冒问号！那我们应该怎么对小派发号施令呢？”
- **互动引导**：“看大屏幕演示（老师点击演示2或按空格键）！‘正前方迈 3 步’——看！小派毫不犹豫，哒、哒、哒三步跳到了金色旗帜！记住：**写程序时不能指望计算机替我们脑补没写清楚的步骤，普通程序不会自动知道没写清楚的规则，必须给出毫无歧义的明确指令！**”

### 2. 环节二：前 10 分钟首秀改代码（真机运行，幕 05~06）
- **教师大屏演示**：“今天我们不背枯燥的概念，直接看代码！看大屏幕，这里有两行神奇的绿色英文字符：`print("你好")` 和 `print("我是小程序员")`。大家先别管括号引号怎么写，今天我们把这一整行，当作一条‘让电脑在屏幕显示一句话’的完整指令。看大屏幕示范：两行代码一运行，终端窗口清清楚楚吐出了这两句话。”
- **切换真实 Python 真机实操**：“但是，光看老师演示不过瘾！现在请大家立刻低头，切换到桌面上老师已经为大家打开好的真实 Python 窗口！
  大家看，里面是不是正好预置好了这两行代码？
  现在，请大家用鼠标把第二行引号里的‘小程序员’选中文本，改成**你自己的名字**（比如‘航天员小明’）！
  改好了吗？抬起小手，点击窗口顶部的绿色 **Run 按钮**（或者键盘上的 F5）！
  ——哇！大家看自己的屏幕下方，是不是弹出了酷酷的黑底终端窗口？里面清清楚楚打印出了你们刚才写的名字！
  太棒了！在开课前 10 分钟，你们每一个人都亲手在真正的 Python 环境里修改并跑通了人生第一段代码！”

### 3. 环节三：关键变式——颠倒顺序实验（幕 11）
- **教师追问**：“同学们，如果老师把代码的顺序故意写反了：第一行写‘完成’，第二行写‘准备’，第三行写‘开始’。我们都知道这在现实里不合理。那老师问大家：电脑那么聪明，它会不会想‘哎呀这小孩写错了，我自作主张帮他倒过来排’？”
- **学生预期反应**：“会！” / “不会！”（课堂产生轻度辩论）
- **教师总结**：“支持‘不会’的同学请举手！老师按下空格键揭晓终端真实结果！——天呐！终端上真真实实地打印出：完成、准备、开始！电脑一点都没有替我们修改！这告诉我们程序员必须恪守的铁律：**计算机只按照你写下的代码顺序执行，而不是按照它觉得‘合理’的顺序执行！顺序错了，责任全在程序员的代码里！**”

### 4. 环节四：Debug 雏形——穿鞋穿袜子（幕 13）
- **教师提问**：“来看看这段代码：`print("穿鞋")`、`print("穿袜子")`、`print("出门")`。老师点一下运行……咦？终端完全没有报错，三个词全蹦出来了！请问这段程序成功了吗？”
- **学生哄堂大笑**：“没成功！哪有光着脚穿上鞋，再把袜子套在鞋子外面的，太搞笑啦！”
- **教师提炼**：“太精彩了！这就是每一个大程序员都会遇到的情况：**程序能运行，绝对不等于程序是正确的！** 如果做出的游戏怪物不会动、计算器算错账，虽然电脑没报错，但逻辑错乱了。这时程序员该怎么做？抱怨电脑坏了吗？不！我们要像小侦探一样，回到代码里调换指令顺序，再运行一次验证它！”

### 5. 环节五：常见意外救场话术（语法报错）
- **学生突发情况**：“老师！我改名片的时候不小心把后面的双引号删掉了，按了回车之后跳出一大堆红字（SyntaxError），电脑是不是被我搞坏了？！”
- **教师救场话术**：“太棒了！你触发了全世界所有顶尖程序员每天都会遇到上百次的‘符号警报’！别害怕，电脑健康得很，它只是个严谨的强迫症——双引号就像两扇对称的大门，有开门就必须有关门。你看不小心漏了后半扇门，电脑不知道你的话在哪结束，所以亮红灯提醒你呢！来，像小侦探一样把双引号补齐，再点一次运行看看？——哇，红字消失，名字跳出来了！你不仅会写代码，连 Debug 查错都学会了！”

## 六、 体验课教师专属诊断观察指南

体验课是了解孩子思维特质的绝佳窗口。教师在课堂巡视与互动中，应重点观察以下 5 项指标（用于因材施教，绝非给孩子贴标签）：

1. **预测意愿度**：在运行代码前，孩子是否愿意先停下鼠标动脑推演，还是急于乱点运行按钮？（引导重点：按住孩子的手，鼓励“说出你的预测再点运行”）；
2. **错误归因倾向**：当结果与预期不一致或出现红色报错时，孩子的第一反应是“电脑坏了/我不会”而发呆，还是好奇地查看代码哪里写错了？（引导重点：强化小侦探角色，赞美发现 Bug 的勇气）；
3. **顺序敏感度**：在进行颠倒顺序实验时，能否敏锐察觉到控制台输出先后顺序与代码行数的对应关系？
4. **自主迁移能力**：在完成基础名片三行代码后，是否有探索欲想要自己尝试加一行代码、或者改换新的文字内容？
5. **键盘与符号认知**：对成对的双引号、括号的配对输入是否具备初步的空间对称感。

## 七、 课后轻量练习与迁移变式

为巩固体验课核心概念，教师可提供以下 4 道轻量趣味口头或动手小挑战，供学生课后与家长共同互动或在真实 Python 中验证：

### 题型 1：生活顺序与指令识别
* **题目**：机器人管家想要制作一杯橙汁，写出了以下三条指令：
  ```python
  print("切开新鲜橙子")
  print("喝一口美味橙汁")
  print("放入榨汁机榨汁")
  ```
  请问：这三条指令能正常在 Python 中运行吗？如果按照这个顺序执行，会发生什么好笑的事情？请你用数字 `1, 2, 3` 排出符合生活逻辑的正确代码顺序。
* **参考解析**：这段代码完全符合 Python 语法，可以正常运行；但逻辑错误（还没榨汁就喝一口）。正确执行顺序应为：1（切开） $\rightarrow$ 3（榨汁） $\rightarrow$ 2（喝橙汁）。

### 题型 2：代码阅读与输出推演
* **题目**：阅读下列三行代码，在不打开电脑的情况下，推演并在草稿纸上写出黑屏控制台最终会显示的文字：
  ```python
  print("3")
  print("2")
  print("1")
  print("发射！")
  ```
* **参考答案**：
  ```text
  3
  2
  1
  发射！
  ```
  （体现从上到下、逐行输出的执行流特点）。

### 题型 3：修改已有代码与个性创作
* **形式**：纸笔预测 / 修改已有代码（可选在已准备好的环境中继续修改，不新建保存文件）
* **题目**：在课上老师已经准备好的代码环境中，或在纸笔草稿上，把程序名片中的自我介绍修改为属于你的梦想宣言（第一行写梦想，第二行写努力方向），先在心里预测输出，再运行验证展示给爸爸妈妈看！
* **参考范例**：
  ```python
  print("我的梦想是成为天文学家")
  print("我要每天观察神奇的星空")
  ```
