# 一、本讲在整套课程中的位置

第01讲已经建立：

> 程序由明确指令组成，代码按照一定顺序执行，结果来自程序执行过程。

第02讲开始正式进入 Python 语言。

但这里不能一下子把重点变成：

> `print()` 的所有语法规则。

本讲真正要完成的认知推进是：

> **程序不仅会执行，还可以把信息表达出来；而程序所处理和表达的内容，本身存在不同的数据形式。**

这是后续变量、数据类型、输入输出的入口。

---

# 二、本讲核心定位

## 一句话定位

> **让学生学会用 `print()` 输出最基础的信息，并第一次意识到：程序中的“文字”和“数字”不是完全相同的东西。**

本讲不是完整的数据类型课。

也不是完整的 `print()` 方法大全。

它只建立：

1. `print()` 是当前用于输出信息的基本工具；
2. 字符串需要用引号表示；
3. 数字和带引号的数字在程序中不是同一种形式；
4. 多条输出语句仍然遵循第01讲建立的执行顺序；
5. 学生开始能够独立写出非常短小、可运行的 Python 程序。

---

# 三、本讲为什么现在教

第01讲已经让学生体验过教师预先准备的：

```python
print("第一步")
print("第二步")
```

但当时只把它当作：

> “让计算机显示一句话的指令”

来使用。

本讲需要正式回答：

> **这一行代码到底是怎么让程序输出信息的？**

因此第02讲不是突然引入新语法，而是拆开第01讲已经体验过的代码。

认知衔接是：

> 看见 `print()`  
> → 用过 `print()`  
> → 现在正式理解并独立使用 `print()`

这比第一讲就一次性讲完更符合儿童学习节奏。

# 五、本讲必须建立的核心认知

本讲真正需要建立四个核心认知。

---

## 核心认知1：`print()` 用来把信息输出出来

学生只需要建立功能层面的理解：

```python
print("Hello")
```

表示：

> 让程序把指定的信息显示出来。

这里不需要展开：
- 函数；
- 参数；
- 返回值。

这些概念远远超出当前认知需要。

---

## 核心认知2：文字需要被程序明确标记

例如：

```python
print("hello")
```

与：

```python
print(hello)
```

在程序眼里不是同一回事。

本讲正式建立：

> **用引号括起来的文字，是字符串。**

学生需要会：
- 单引号；
- 双引号；
- 引号成对。

但本讲重点不是研究各种引号技巧，而是：

> **字符串需要明确边界。**

---

## 核心认知3：数字与字符串形式不同

例如：

```python
print(10)
```

和：

```python
print("10")
```

最终屏幕上看起来都可能显示：

```text
10
```

但程序内部并不把它们当作完全一样的东西。

本讲不要求学生掌握：
- `int`
- `str`
- 类型转换

但必须埋下一颗非常重要的种子：

> **“看起来一样”不代表程序中的数据性质一样。**

这会为：
- 第03讲变量；
- 第05讲运算；
- 第08讲input；
- 第09讲类型转换；

留下清晰接口。

---

## 核心认知4：多行代码仍然按照顺序执行

第01讲已经体验过顺序。

第02讲要正式回收，而不是学完就丢掉。

例如：

```python
print("准备")
print("开始")
print("完成")
```

学生需要能够：

> 看代码 → 预测输出 → 运行验证。

这条训练从第02讲开始应该成为常态。

# 十一、字符串概念教到什么深度

本讲只要求：

> **字符串是程序中用来表示文字信息的一种数据形式，通常写在引号里面。**

学生能识别：

```python
"深圳"
"Python"
"123"
```

都是字符串。

即可。

不要求背：

> str 是不可变序列类型……

这种定义不属于本课程当前层级。

也不要求本讲使用 `str` 这个类型名进行大量记忆。

可以轻量告诉学生：

> Python里这种文字数据叫字符串。

认知优先于术语。

# 十二、数字数据教到什么深度

本讲只需要让学生知道：

```python

3.14
```

属于数值形式。

暂时不需要完整区分：

- int；
- float。

真正的整数、浮点数精确分类，可以随着第05、08、09讲进一步自然建立。

本讲只需要形成：

> **数字可以直接作为数值写入程序，而文字需要引号。**

# 十三、本讲最重要的认知冲突

本讲建议至少设计一个：

```python
print(10)
print("10")
```

然后问：

> 屏幕上看起来差不多，那它们是不是一样？

先允许学生猜。

教师不需要马上讲复杂解释。

只需要给出结论：

> **对人眼来说看起来相同，但对程序来说，一个是数字，一个是文字。以后当它们参与计算时，差别就会真正出现。**

这里应该刻意留下悬念。

因为后面第05讲运算、第08～09讲输入转换会重新回收。

这种“先埋种子，后续长出来”的方式，比现在一次讲完整数据类型更好。

# 十四、本讲程序思维训练点

虽然本讲主要是基础语法，但不能退化成“记格式”。

需要继续维持三条思维训练。

## 1. 执行顺序继续出现

每次多行代码都先预测。

---

## 2. 代码中的符号有明确意义

引号不是装饰。

它告诉程序：

> 这里是一段文字数据。

程序不会“看着差不多就懂”。

这与第01讲：

> 计算机不会猜人的意思

形成非常自然的连接。

---

## 3. 结果与代码结构对应

学生需要逐渐能从输出反推：

> 哪一行代码产生了哪一行结果。

这是未来 Trace 的基础。

# 十五、本讲题型递进

---

## 第一层：基础题

### 目标
确认学生能正确识别基础 `print()`。

例如判断：

```python
print("Hello")
```

会输出什么。

以及：

```python
print(123)
```

会输出什么。

---

## 第二层：同构题

改变内容：

```python
print("Python")
print("深圳")
print(2026)
```

验证学生掌握的是规则，不是记住原例。

---

## 第三层：错误识别

例如：

```python
print("Hello)
```

或：

```python
print(Hello)
```

重点讨论：

> 程序中的文字需要怎样明确标记？

注意错误代码要控制复杂度。

本讲不是 SyntaxError 专题。

---

## 第四层：顺序预测

```python
print("第一")
print("第二")
print("第三")
```

先预测，再运行。

---

## 第五层：变式

把代码顺序打乱：

```python
print("第三")
print("第一")
print("第二")
```

学生预测结果。

---

## 第六层：小综合

给出要求：

> 让程序依次输出：
>
> 我的名字  
> 我喜欢的东西  
> 一个幸运数字

学生独立写三行。

这里只要求固定输出。

不允许为了“信息卡更高级”提前引入变量、input、f-string。

# 十九、本讲常见错误及课研处理原则

## 错误1：忘记引号

```python
print(hello)
```

当前学生尚未学变量。

处理方式：

> 告诉学生程序会把没有引号的 hello 当成另一种代码含义，而不是一段普通文字。

不需要现在展开 NameError 和变量查找机制。

---

## 错误2：中英文符号混用

例如中文引号或中文括号。

这是文字编程早期非常真实的问题。

需要让学生逐渐形成：

> **代码符号必须准确。**

但不要因此把课堂变成符号纠错大会。

---

## 错误3：括号、引号不成对

通过视觉配对和简短错误定位解决。

---

## 错误4：认为 `"10"` 就是数字10

本讲只纠正：

> 它是文字形式的“10”。

不提前进入类型转换。

---

## 错误5：把输出顺序凭直觉看

继续要求：

> 从第一行开始，一行一行看。

# 二十七、本讲最终课研结论

第02讲是整套课程第一次真正的 Python 语言课。

但它的任务仍然非常克制：

> **让程序表达信息，让学生第一次准确地区分“文字”和“数字”这两种最基本的数据形式，并继续强化程序按顺序执行的意识。**

这一讲不追求内容多。

真正成功的标志是：

> 学生开始能够自己敲下一段代码，知道每个关键符号不是装饰，并习惯先预测程序会发生什么，再点击运行。
