# 一、本讲在整套课程中的位置

第03讲已经完成了一个重要转折：

> 程序不只是输出信息，它还可以把数据“记住”。

学生已经知道：

```python
x = 10
```

表示把 `10` 赋给变量 `x`。

也已经轻量接触：

```python
x = 10
x = 20
```

并知道后一次赋值会更新变量当前保存的值。

但第03讲只回答了：

> **变量可以改。**

第04讲要进一步回答：

> **变量究竟是怎样一步一步变化的？**

这是后续几乎所有程序阅读能力的地基。

如果这一讲没有站稳，学生后面遇到复杂表达式、if、for、while、累加器、计数器、数位拆解、最大值更新时，都容易凭感觉看代码。

所以第04讲的核心价值非常高。

# 二、本讲核心定位

> **让学生真正建立“程序一行一行执行，变量保存的是当前值，每执行一条赋值语句，状态就可能被更新”的思维模型。**

本讲不是“再学一种赋值”。

真正核心是：

> **程序状态如何随执行顺序变化。**

# 三、本讲为什么现在教

第03讲留下了天然接口：

```python
x = 10
x = x + 1
```

学生第一次看到这段代码，通常会产生冲突：

> `x` 怎么会等于 `x + 1`？  
> 这在数学里不是不成立吗？

这正是非常好的认知入口。

它迫使学生彻底抛开“`=` 是数学等号”，转而采用程序执行视角：

> **先取出右边当前的值，算出结果，再把新结果赋回左边。**

第04讲必须把这个规则建立得非常牢固。

# 五、本讲必须建立的核心认知

## 核心认知1：变量保存的是“当前值”

例如：

```python
x = 10
x = 20
```

不能说：

> x同时等于10和20。

而应该说：

> 第一行执行后，x 当前是10。  
> 第二行执行后，x 当前更新成20。

学生必须开始习惯问：

> **现在是多少？**

而不是“以前出现过哪些值”。

## 核心认知2：`x = x + 1` 必须从右往左理解赋值

```python
x = 10
x = x + 1
```

正确执行过程：

1. 先找到右边 `x` 当前值：10；
2. 计算 `10 + 1`：得到11；
3. 把11重新赋给左边的 `x`；
4. 此时 `x` 当前值变成11。

本讲最重要的阅读习惯：

> **先算右边，再更新左边。**

## 核心认知3：旧值会被新值覆盖

程序运行到：

```python
x = x + 1
```

完成后，变量当前保存的是新值。

当前学习层级使用“覆盖 / 更新”即可，不进入内存地址、对象引用等底层机制。

## 核心认知4：程序执行顺序决定状态变化顺序

例如：

```python
x = 5
x = x + 2
x = x + 3
```

状态不是一下子跳到10，而是：

```text
5 → 7 → 10
```

学生必须学会逐行跟踪。

## 核心认知5：多个变量各自维护自己的当前值

例如：

```python
a = 3
b = 5
a = a + 2
b = b + 1
```

学生要能够分别跟踪：

- `a` 当前值；
- `b` 当前值。

这是以后中间变量、累加器、计数器、while 多状态的直接前置。

# 十、Trace 到底教什么

本讲必须避免把 Trace 教成：

> “画表格填答案”。

真正目标是让学生形成执行语言：

> 第一行执行后，x 当前是多少？  
> 第二行右边先取哪个值？  
> 右边算完是多少？  
> 赋值完成后，x 更新成多少？

学生最终即使不画表，也应该能按这个思路推。

所以：

> **Trace Table 是思维支架，不是最终目标。**

# 十一、本讲最重要的认知冲突

## 冲突1：数学等式 vs 程序赋值

```python
x = x + 1
```

这是本讲最核心冲突。

必须明确：

> 数学里它可能是一个等式判断问题；Python里这里的 `=` 是赋值操作。

## 冲突2：右边使用旧值，左边得到新值

```python
x = 10
x = x + 1
```

第二行执行时：

- 右边的 `x` 读取当前旧值10；
- 右边计算得到11；
- 整行执行完成后；
- 左边的 `x` 更新为11。

## 冲突3：输出看到的是“那个时刻”的值

```python
x = 5
print(x)
x = x + 2
print(x)
```

两次输出不同，因为两条 `print()` 执行时的状态不同。

# 十二、本讲程序思维训练点

## 1. 状态不是静态数据
变量的值会随着程序执行改变。

## 2. 每一行代码都可能改变程序状态
程序执行前后，状态可能不同。

## 3. 阅读代码必须有时间顺序
不能把整段程序同时看成一个数学式子。

必须问：

> **执行到这一行时，变量现在是多少？**

## 4. 状态需要被维护
即使当前只有两个变量，也要开始形成：

> 程序里不同变量承担不同状态。

# 十三、本讲题型递进

## 第一层：单次重新赋值


## 第二层：单次基于旧值更新


目标：确认右值计算与左值更新。

## 第三层：连续更新

```python

x = x + 3
x = x + 4
print(x)
```

目标：逐行跟踪。

## 第四层：插入输出

```python

print(x)
x = x + 3
print(x)
```

目标：理解输出反映的是“执行到当时的当前值”。

## 第五层：两个变量分别更新

```python
a = 2
b = 5
a = a + 1
b = b + 2
```

目标：分别维护多个状态。

## 第六层：两个变量相互引用的最简版本

```python

b = a
a = 5
print(a)
print(b)
```

目标：

> `b = a` 执行时，b得到的是当时a的值。后面a变化，不意味着b自动跟着变化。

当前只按“值的结果”理解即可，不讨论底层引用机制。

## 第七层：小综合 Trace

给4～6行变量程序，让学生：

1. 先自己推；
2. 填简单状态表；
3. 最后运行验证。

# 十四、一个重要变式：`b = a`

本讲建议一定出现：

```python
a = 3
b = a
a = 5
print(b)
```

学生常见误判：

> b最后也是5。

正确认知：

> 执行 `b = a` 的那个时刻，a当前是3，于是b得到3。后面a更新成5，不会自动把b一起改掉。

这是非常重要的“赋值发生在当前时刻”的证据。

它能强化：

> **程序状态是逐行更新，不是变量之间永久绑定。**

# 十八、本讲常见错误及处理原则

## 错误1：把 `x = x + 1` 当数学等式
处理：强制切回执行过程，右边先算，左边后更新。

## 错误2：跳过中间状态直接猜最终答案
处理：要求逐行说“现在是多少”。

## 错误3：把旧值和新值同时当成当前值
处理：每执行完一次赋值，当前值只有最新结果。

## 错误4：认为变量之间会永久绑定
例如：

```python
a = 3
b = a
a = 5
```

学生认为 `b` 也变5。

处理：回到“`b = a` 那一行执行时发生了什么”。

## 错误5：Trace表填写的是“这一行出现了什么”，而不是“执行后状态”
表头最好明确写：

> **执行这一行后**

## 错误6：把所有变量混成一个过程
处理：每个变量单独一列。

```text
现在是5
下一行以后可能是6
再下一行以后可能是10
```

所以理解程序，不能只看代码“写了什么”，还要看：

> **执行到这一刻，程序现在处于什么状态。**

这正是后续循环、算法和状态模拟的底层能力。

---

# 最终一句话

> **第04讲真正要教会孩子的，是把代码从“静态文字”看成“会一步一步改变程序状态的执行过程”。**
