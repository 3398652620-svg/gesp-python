## 一、 教学定位与核心目标

### 1. 本讲核心定位
> **让学生真正建立“程序一行一行执行，变量保存的是当前值，每执行一条赋值语句，状态就可能被更新”的思维模型。学会使用简单 Trace Table（跟踪表）逐行追踪单变量与多变量的执行状态。**

本讲是整套课程中最关键的“程序阅读能力与状态思维奠基课”。学生从此脱离“把代码当静态文字看”的初级阶段，开始建立**“程序是在时间中运行、状态一步一步演进”**的高阶思维。

> **自然显性成果定位**：依据38讲课次地图上位标准，本讲**“自然显性成果：无，不强行包装”**。学生通过独立编写、预测与运行 4~6 行多变量状态程序（`trace_04.py`）完成能力验证。

### 2. 核心素养与教学目标
1. **赋值机制本质深化**：深刻理解 `x = x + 1` 的执行本质是**“先计算右边当前表达式的结果，再把新结果赋给左边的变量名保存”**，彻底打破数学等号永恒相等的认知干扰；
2. **状态覆盖与当前值更新**：理解赋值语句执行完成后，旧值被新值覆盖，变量当前只保存最新计算结果；
3. **时间与顺序维度**：理解连续赋值（如 `x = 2; x = x + 3; x = x + 4`）的状态变化是 `2 → 5 → 9` 逐步演进的，`print()` 输出反映的是**“执行到那一瞬间的当前值”**；
4. **多变量状态独立维护**：能够同时跟踪两个变量（如 `a` 和 `b`）的独立状态演进，互不干扰；
5. **关键认知变式突破**：深刻理解 `b = a` 发生在那一瞬间，是将当时 `a` 的值赋给 `b`，后续 `a` 的修改**绝对不会**自动带动 `b` 改变；
6. **Trace Table 支架工具**：学会使用包含“行号 / 执行语句 / 变量当前值 / 未赋值状态”的跟踪表推演程序；
7. **真实实战与排错**：在本地 Python IDE 中独立编写 `trace_04.py`，先在草稿纸或脑海中独立完成 Trace Table 预测，再运行验证。

## 二、 教学重难点与认知边界

### 1. 教学重点
- `x = x + 1` 的右算左赋执行机制（先右后左）；
- 变量状态随时间演进模型；
- 多变量独立跟踪与 Trace Table 使用；
- `b = a` 变式理解。

### 2. 教学难点
- 克服“`x = x + 1` 在数学上不成立”的直觉困惑；
- 避免跳过中间过程直接靠感觉猜最终答案；
- 纠正“`b = a` 会让两个变量永久绑定”的错误直觉。

### 3. 严格禁止超纲禁区（守卫底线）
- ❌ 严禁提前正式教授 `+=`、`-=` 等复合赋值运算符（留给后续课次）；
- ❌ 严禁引入复杂算术优先级与大量 `/ // % **`（数学运算仅使用最简单的 `+1/+2/+3` 服务状态演进）；
- ❌ 严禁提前引入 `input()`、类型转换 `int()` / `str()`、`if` 条件、`for/while` 循环、函数、列表；
- ❌ 严禁提前展开 Python 底层内存地址、指针与对象引用模型理论。

## 四、 课堂显性操作与家校反馈话术

### 1. 显性操作任务（能力验证）
* 学生在本地环境独立编写、预测、运行并保存的代码文件：`trace_04.py`

  ```python
  a = 10
  b = 5
  a = a + 2
  b = a + b
  print(a)
  print(b)
  ```
