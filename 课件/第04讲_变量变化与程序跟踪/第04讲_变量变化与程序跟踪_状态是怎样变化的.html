认知冲突

x = x + 1 为什么数学里不成立，Python 里很常见？🤔

📐 数学视角（等式判断）
x = x + 1 ➔ 0 = 1 ❌ (荒谬！)
在数学中，= 表示两边永远相等。任何数字都不可能等于自己加 1！
💻 Python 执行视角（动作指令）
x = x + 1 ✅
在 Python 中，= 是赋值操作！表示：算出右边的新结果，存回左边的变量里！
🌟 核心认知：代码中的 = 是动作指令（赋值），绝非数学里的永恒相等！
执行机制

赋值黄金法则：先算右边，再赋给左边 ⬅️

假设当前 x=10 ➔ x = x + 1
1. 取出右边当前值
找到右边 x 当前保存的旧值 10
2. 算出右边新结果
计算 10 + 1 得到结果 11
3. 赋回左边覆盖旧值
把 11 存入变量 x，旧值 10 被覆盖！

状态演进

连续多次更新：状态是一步步演进的 📈

steps_count.py
1x = 5
2x = x + 2
3x = x + 3
⏱️ 状态演进时间线：
① 初始状态：x = 5 ➔ 当前值为 5
② 执行第 2 行：5 + 2 ➔ 当前值更新为 7
③ 执行第 3 行：7 + 3 ➔ 当前值更新为 10
🌟 核心认知：变量状态是一行行按顺序演进的（5 ➔ 7 ➔ 10），不是瞬间跳出来的！

思维支架

认识 Trace Table：把程序状态一步一步记下来 📊

📋 为什么我们需要 Trace Table？
当程序有多个变量、多步赋值时，只靠脑子容易记混。
Trace Table（状态跟踪表） 可以帮助我们稳定记录每一行代码执行后的当前状态。
📋 跟踪表三大核心列：
执行步骤 / 行号 变量 a 当前值 变量 b 当前值
a = 3 3 未赋值
b = 5 3 5
🌟 核心法则：每一行只记录“该语句执行完成后”变量的最新当前值！

多变量状态

多变量状态：各自管理自己的专属记忆 👥

🅰️ 变量 a 的独立时间线
• 第 1 行初始化为 3
• 第 3 行执行 a = a + 2 更新为 5
变量 a 只关注自己的更新指令！
🅱️ 变量 b 的独立时间线
• 第 2 行初始化为 5
• 第 4 行执行 b = b + 1 更新为 6
变量 b 的数值不会被 a 的计算打扰！
🌟 核心认知：每个变量都各自维护自己的当前值，互不干扰！
关键变式

关键认知变式：b = a 会把变量永久绑定吗？🔗❌

link_test.py
1a = 3
2b = a
3a = 5
4print(b)
❓ 思考：第 4 行 print(b) 输出几？
• 第 2 行 b = a 执行时，只把 a 当时的值 3 复制给了 b！
• 第 3 行 a 改成了 5，绝对不会自动把 b 连带着改掉！
• 所以 b 依然保存着 3！
🌟 核心金句：赋值只发生在当前时刻，绝不是建立永久连线！
