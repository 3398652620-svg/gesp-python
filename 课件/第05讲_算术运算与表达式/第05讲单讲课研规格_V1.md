# 一、本讲在课程中的位置

前四讲完成了这条认知链：

> 程序会执行  
> → 程序可以输出  
> → 程序可以保存数据  
> → 程序中的数据会随执行过程发生变化

第04讲尤其已经建立：

> **先计算赋值号右边，再把结果更新给左边。**

例如：

```python
x = 5
x = x + 2
```

学生已经能够理解右边的 `x + 2` 会先算出结果。

第05讲顺着这个接口继续追问：

> **右边除了“+2”，数据之间到底还可以怎样计算？**

因此本讲不是孤立地背六个运算符，而是把学生已经建立的“程序状态”继续推进到：

> **数据可以通过表达式被加工，表达式计算出的结果又可以成为新的程序状态。**

这也是第06讲“复杂表达式与运算顺序”的必要前置。

---

# 二、本讲核心定位

一句话：

> **让学生理解 Python 中常见数值运算的真实意义，并能够把简单数学关系翻译成 Python 表达式。**

本讲真正要建立的不是：

> “记住 `+ - * / // %` 六个符号。”

而是：

1. 运算符描述了“数据之间要做什么计算”；
2. 表达式会计算出一个结果；
3. 变量可以参与表达式，读取的是变量当前保存的值；
4. 表达式的结果可以继续被变量保存或输出；
5. `/`、`//`、`%` 表达的是三种不同的除法相关结果。

---

# 三、学生进入本讲时已经具备什么

学生已经学过：

- 数值与字符串的初步区别；
- `print()`；
- 变量；
- 赋值；
- 重新赋值；
- 变量当前值；
- 连续状态变化；
- 简单 `+1`、`+2`、`-1` 更新；
- “先算右边，再赋给左边”；
- 简单 Trace。

因此：

> **本讲不需要重新讲变量和赋值。**

但应自然回收第04讲的执行模型，让学生看到：

```python
a = 8
b = 3
c = a * b
```

执行到第三行时，是读取 `a` 和 `b` 的当前值，完成乘法，再把结果保存到 `c`。

# 四、本讲必须建立的知识与认知

## 1. Python 的基本算术符号

本讲正式覆盖：

- `+` 加法
- `-` 减法
- `*` 乘法
- `/` 普通除法
- `//` 整除 / 向下取整除法
- `%` 取余

学生要能完成“数学符号 → Python符号”的转换，尤其避免：

- 把乘号写成 `×`；
- 把除号写成 `÷`；
- 混淆 `/` 与 `//`。

---

## 2. 什么是“表达式”

不需要给出过于形式化的定义。

学生至少应形成：

> **把数据、变量和运算符组合起来进行计算，就形成了一个会产生结果的表达式。**

例如：

```python
8 + 3
price * count
n // 10
n % 10
```

这里的重点是“会算出结果”，而不是背术语。

---

## 3. 变量可以参与运算

学生应能够从：

```python
8 * 3
```

迁移到：

```python
price = 8
count = 3
total = price * count
```

并理解：

> 变量参与表达式时，程序读取的是它在当前时刻保存的值。

这一点必须与第04讲状态模型保持连续。

---

## 4. `/` 与 `//` 的区别

这是本讲第一个真正需要花认知资源的点。

在 Python 3 中：

```python
7 / 2
```

得到：

```text
3.5
```

而：

```python
7 // 2
```

在本阶段使用的非负数情境下得到：

```text
3
```

还应让学生看到：

```python
8 / 2
```

结果是：

```text
4.0
```

因此不能把 `/` 简单理解为“有余数时才有小数”。

### 本讲范围控制

为避免把“负数向下取整”的细节变成新负担，本讲 `//` 的教学实例以**非负整数**为主。

教师如果需要使用“整除”这一儿童易理解说法，可以使用，但不能建立错误规则：

> “`//` 永远只是把小数部分砍掉。”

Python 的真实语义是 floor division，本讲只是不展开负数情况。

---

## 5. `%` 的余数意义

本讲只建立：

> **把数据按某个数量一组一组分完以后，还剩多少。**

例如：

```python
17 // 5   # 能完整分成几组
17 % 5    # 分组以后还剩几个
```

学生需要真正理解“商”和“余数”是同一次分组问题的两个不同答案。

`%` 在本讲先作为“求余数”的运算理解。

它后续会被重新激活用于：

- 第14讲奇偶与周期；
- 第19讲筛选；
- 第20讲因数与质数；
- 第23讲数位拆解。

所以这里必须把“余数”本身讲稳，但**不提前把后面的算法用途一次讲完**。

---

# 五、本讲最重要的认知主线

Gemini 的讲法可以自由变化，但最终应让学生经历并理解这条链：

> 数据可以计算  
> → Python 用运算符描述计算  
> → 表达式会得到结果  
> → 变量可以把当前值送进表达式  
> → 结果还可以重新保存  
> → 除法相关问题中，`/`、`//`、`%`回答的是不同问题

不要求课件逐字显示这条链，也不要求按完全相同的页面顺序展示。

它是课程逻辑，不是页面脚本。

# 六、必须出现的学习经历

这里规定“学生必须真正做过什么”，不规定具体故事或页面形式。

## A. 从熟悉数学关系进入 Python 符号

至少让学生把若干简单关系翻译成 Python，例如：

- 8 加 5
- 12 减 4
- 6 乘 7
- 15 除以 3

目标不是题量，而是确认 Python 运算符已经建立。

---

## B. 数字表达式 → 变量表达式

学生不能只会：

```python
8 * 3
```

还要能理解或写出：

```python
price = 8
count = 3
total = price * count
```

至少经历一次：

> **固定数字 → 用变量表达同一个关系**

这是后续编程建模的基础。

---

## C. `/`、`//`、`%` 三者对比

必须使用同一组数据进行对比，让学生看到三个结果回答不同问题。

例如可以使用：

```python
17 / 5
17 // 5
17 % 5
```

具体数字、故事、动画表现由 Gemini 自由选择。

---

## D. 先预测，再运行验证

至少有一组任务要求学生：

> 先说/写结果 → 再运行程序 → 对照自己的判断

本讲不能退回“老师演示，学生看结果”的方式。

---

## E. 从自然语言写出表达式

至少让学生独立完成一类“关系翻译”，例如：

> 每本书 12 元，买 4 本，一共多少钱？

学生真正要完成的是：

```python
price = 12
count = 4
total = price * count
```

情境可以替换。

核心是：

> **读懂数量关系 → 选择运算 → 写成 Python 表达式。**

# 七、题型成长方向

本讲题型应大致完成以下递进，不要求机械地分成固定页数。

### 基础
识别和使用单一运算符。

### 同构
数字换成变量，关系不变。

### 对比
同一组数据比较 `/`、`//`、`%`。

### 变式
给一个简单生活数量关系，让学生判断应该使用哪一种运算。

### 独立小任务
用若干固定变量完成一个短小“保存 → 计算 → 输出”程序。

本讲不追求大型项目。

---

# 八、核心易错点

教学中至少应能捕捉以下错误。

## 1. 使用数学里的 ×、÷

需要明确转换为 Python 的 `*`、`/`。

## 2. 把 `/` 和 `//` 当成同一个东西

应通过同数据对比建立差异。

## 3. 把 `%` 理解成“百分号”

在 Python 算术表达式中，本讲的 `%` 表示取余。

## 4. 只会算数字，不会让变量参与表达式

必须完成数字 → 变量迁移。

## 5. 看见变量表达式就忘记“当前值”

例如：

```python
a = 5
a = a * 2
```

应继续沿用第04讲执行模型，而不是把它当静态数学等式。

## 6. 把表达式复杂度提前拉高

如果学生错误来自“先乘还是先加”，说明任务已经进入第06讲的主认知。

本讲应及时收住。

# 十、80分钟容量护栏

本讲新符号数量较多，但真正高认知负荷主要集中在：

- `/` vs `//`；
- `%`；
- 数学关系 → Python 表达式。

因此不要把课堂做成“六个运算符逐个讲定义、逐个抄例题”的符号清单课。

在约80分钟有效教学中，应保证学生有真实时间进行：

- 判断；
- 预测；
- 计算；
- 写表达式；
- 修改；
- 运行验证；
- 独立完成至少一个短程序。

如果课堂时间不足，优先减少：

- 重复同构题数量；
- 运算符的额外包装故事；
- 不必要的背景知识；
- 非核心拓展。

不能为了赶页面而压掉学生独立表达和运行验证。

# 十二、学生课件实现边界

学生看到的 HTML 应是正常课堂，而不是研发文档的投影。

学生页面不要出现类似：

- “本讲不首次教授……”
- “当前知识边界……”
- “根据课研规格……”
- “后续第14讲会……”
- “非考纲……”
- “上位文件规定……”

这些属于研发层语言。

课件应该让学生看到的是：

> 问题、代码、预测、实验、计算、选择、修改、运行、反馈。

动画优先用于帮助理解：

- 运算发生了什么；
- 数据怎样进入表达式；
- `/`、`//`、`%` 的结果差异；
- 变量当前值怎样被读取。

不要为了“有动画”而做与认知无关的装饰性运动。

# 十三、本讲能力出口

课末学生至少应能做到：

1. 正确使用 `+ - * / // %`；

# 十五、给第06讲留下的接口

第05讲结束后，学生已经知道：

> **数据可以通过不同运算符组成表达式并得到结果。**

但当前任务应主要是单一运算或运算顺序非常明确的表达式。

接下来自然产生新问题：

```python
2 + 3 * 4
```

到底应该先算什么？

于是第06讲进入：

> **复杂表达式与运算顺序**

正式建立：

- `**`；
- 括号；
- 常见运算优先级；
- 同级运算顺序；
- 复杂表达式跟踪。

因此第05讲不要提前把第06讲讲完。
